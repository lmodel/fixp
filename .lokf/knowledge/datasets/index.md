# Datasets

* [The fixp LinkML schema](fixp-linkml-schema.md) - The umbrella schema `src/fixp/schema/fixp.yaml`, which imports the core, messages, exchange and engagement modules and is the file the project names. It pins FIXP 1.0 at the tag `v1.0-STANDARD`.
* [The core module](core-module.md) - `fixp_core`: FIXP's datatypes, such as `fixp_uuid`, `fixp_nanotime` and `fixp_object`; the value lists, such as `FixpFlowType` and the four reject and termination codes; the fields the messages share; and the abstract `FixpMessage`.
* [The messages module](messages-module.md) - `fixp_messages`: the nineteen FIXP messages as classes with the `Fixp` prefix, from `FixpNegotiate` to `FixpMessageTemplate`, each with its fields in the specification's order and annotations for its template id, sender and flow types.
* [The exchange module](exchange-module.md) - `fixp_exchange`: `FixpExchange`, the tree root, a run of messages on one session, and `FixpExchangeStep`, which holds one message or a count of application messages and the side that sent it.
* [The engagement module](engagement-module.md) - `fixp_engagement`: `FixpRulesOfEngagement`, the checklist of the specification's appendix B, with a `FixpStackProfile` each for the client and the server.
* [The adapt copy](adapt-copy.md) - `.lokf/fixp.yaml`, which `just lokf-adapt` writes from the schema so that it can sit beside LOKF's: the file this bundle validates against, and the file a release attaches as `schema-<tag>-fixp.yaml`.
* [The neighbours' copies](neighbour-copies.md) - `tests/neighbours/`: the adapt copies other lmodel repositories release, each the release's schema asset, which tests use to hold this copy's names apart from theirs, fix-sbe's, fix-orchestra's and fix-protocol's among them.
* [The generated artefacts](generated-artefacts.md) - What the generators write from the schema: `project/`, `src/fixp/datamodel/` and `docs/schema/fixp.yaml`. They are committed and never edited.
* [The example data](example-data.md) - `tests/data/`: a valid example of every class, four whole exchanges, and a counter-example per constraint, named `ClassName-suffix.yaml`, each counter-example naming where it fails on its first line.
* [The copy of the upstream](upstream-copy.md) - `upstream/`: FIXP 1.0's SBE schema, FIX repository file and Orchestra file, with the repository's CC BY-ND 4.0 licence, unchanged and pinned by git object hash in `scripts/upstream_pins.tsv`.
* [The departures from FIX's files](upstream-departures.md) - `tests/upstream_departures.yaml`: each place the schema differs from a resource file, with its reason, such as Topic's keep-alive interval and Context's next sequence number, and the note that the Orchestra file is not well-formed.
* [An exchange as a concept](example-exchange.md) - The shortest point-to-point start, a Negotiate and its NegotiationResponse, written as a concept of type `FixpExchange`. It shows that the domain schema admits an exchange as a concept.
* [Rules of engagement as a concept](example-rules-of-engagement.md) - A client and a server that use SBE over TCP with TLS 1.3, written as a concept of type `FixpRulesOfEngagement`. It shows that the domain schema admits the appendix B checklist as a concept.
